# Issue #41, `<2> + 0` retained checks: what was supported, and where the boundary is

Provider `42d7361c` (staged tree `~/sage-extensions-42d7361c`), port: the commit this note is in.
Evidence: `tests/test_degenerate_pointed_markings.py`, 57 tests, 102.72 s, peak tree RSS 3895 MiB (Julia baseline
3149, python 733); whole unit suite `-m "not slow"`, 304 passed, 2 deselected, 208.02 s, peak 4433 MiB (Julia 3188,
python 1232). The original seven checks were 71 s / 3628 MiB on provider `565fc6b9`, port `350e0569`.

## What was already supported (measured, before writing any test)

The four retained checks pass on the *current* port, through the public pointed operations:

| check | result |
| --- | --- |
| `(1,0) -> (1,1)` | witness, column matrix `[[1,0],[1,1]]`, det 1, carries the vector correctly |
| `(5,1) -> (5,6)` | same shear `[[1,0],[1,1]]` |
| `(5,1) -> (5,2)` | **no witness**, while `q = 50`, `content = 1`, `div = 10` all agree |
| `O(L)_{(1,0)}` | generated by `diag(1,-1)`, **order 2**, fixes `(1,0)` pointwise |

So the "extension requirement" of the issue is, for these examples, already met by the existing pointed
recursion: for a non-isotropic `v` it goes through `v^perp` (here the radical), extends across `v`, and then
corrects integrality against `_lattice_action(target).transporter(...)`. The split-radical block construction
written up in the issue body was **not** needed for them.

Two traps I got wrong on the way, recorded so they are not repeated:

- `(5,1) -> (5,2)` in the rank-**two** radical lattice `C + R = <2> + 0 + 0` **does** have a transporter. I
  first expected a refusal reasoning that the first column of `D` would have to be `(2,0)`, which is not
  primitive; but `D = [[2,1],[5,3]]` has determinant 1 and first column `(2,5) = (2,0) mod 5`, so the
  condition `s - D r in 5R` holds. The code was right and my expectation was wrong.
- A `TypeError` from `isomorphisms(...)` was my own doing: `pointed()` builds a *fresh* `pointed_category`
  per call, so two such objects are not objects of the category passed alongside them. Building both
  markings inside one category instance works, for degenerate and nondegenerate lattices alike.

## What is pinned now

`tests/test_degenerate_pointed_markings.py`:

1. `(1,0) -> (1,1)` exact shear, determinant 1, Gram-preserving;
2. `(5,1) -> (5,6)` same shear;
3. `(5,1) -/-> (5,2)` refusal, with the three naive invariants first shown equal;
4. pointwise stabilizer of `(1,0)`: order 2, contains `diag(1,-1)`;
5. the public pointed `Aut`/`Isom` consumers reach the same verdicts, via `underlying_isometry`;
6. a presentation with the radical in the **first** coordinate transports correctly (`[[1,1],[0,1]]`), so
   the route is not a Gram-block special case;
7. the unmarked radical `Aut` route still generates the negation and the shear and has order > 2.
8. **radical rank 2, mixed markings** (`L = <2> + 0 + 0`, `v = (5, r)`, `R = Z^2`): six transports, each with the
   `[[A, 0], [B, D]]` block built by hand from the conditions and checked before the port is asked -- unimodular,
   `g^T G g = G`, and `g v = w`. Three refusals, each separated by `content` (a proved invariant) rather than by the
   residue, which at rank 2 is everything.
9. **the rank-one sign, both ways**: `(5,1) -> (5,4)` and `(5,2) -> (5,3)` transport by the negating radical unit,
   and `(5,2) -> (-5,2)` by `A = -1` -- the symmetry of `C`, not a transporter. `(5,2) -> (5,1)` is refused, and
   that refusal is a finite exhaustion of the four candidate blocks (`A` irrelevant as `x = y`, `d` in `{+-1}`),
   not a bounded search; `q`, `content` and the divisibility all agree on that pair, so none of them explains it.
10. **the congruence image itself**, `radical_congruence_image`: its `MatrixGroup` order checked against
    `|GL_k(Z/n)| * 2 / phi(n)` (from `GL(...).order()` and `euler_phi`) for `k` in `{1,2,3}` and `n` in
    `{2,3,4,5,6,7,8,13}`; `diag(2,1) mod 5` excluded by `contains`; the image proper at `n = 5` (index two) and the
    whole group at `n = 6`; and `n = 13`, whose image has order 4368, answered with no bound at all.
11. **the sign generator is the diagonal matrix it claims to be** -- a targeted witness for a construction defect:
    the removed `_signed_diagonal` produced an all-minus first row (`(-1,-1,...)`), which is unimodular and so
    passed every determinant check in place. The test reads the first row of the retained generator for ranks two
    and three, compares it with `diagonal_matrix(ZZ, [-1,1,...])`, and also pins the defective shape as a matrix
    that must *not* be built.
12. **the rank-one/rank-two contrast**, stated correctly: `(5,1) -> (5,2)` refused at radical rank 1 and
    `(5,1,0) -> (5,2,0)` transported at radical rank 2, same norm, content and residue data. Not because the image
    is onto at rank two -- it is not, `|im| = 240 of 480` -- but because `transporter` returns an integral
    unimodular carrier and `orbit_of((1,0))` has the 24 nonzero residues. Transitivity is computed by GAP's
    `Orbit`, never inferred from the group map.
13. **the pointwise stabilizer against the congruence count**: `(5,1)` rigid (order 1), `(5,0)` order 2, `(1,0)`
    order 2 with the congruence vacuous at `c = 1`, and the rank-two mixed marking infinite while its congruence
    part is `stabilizer_order((1,0)) = 10`. The finite count is an image, never an order.

## Retraction: the image of `GL(R)` in `Aut(R/cR)` is not the whole residue group

An earlier revision of this note, and the test docstrings it accompanied, claimed that for `k >= 2` the map
`GL_k(Z) -> GL_k(Z/n)` is **onto**, that the residue condition could therefore be read as the whole of
`GL_k(Z/n)`, and that the image is a proper subgroup "exactly at rank one". Both clauses are false. The issue body
had already stated the correct caveat, and it is binding:

> the relevant finite permutation action is that of the *image of `GL(R)`* in `Aut(R/cR)`. It need **not** be the
> full group `GL(R/cR)`; over `Z`, a lifted integral automorphism has determinant `+-1`.

A lift is integral and unimodular, so its determinant is `+-1`, and

    im(GL_k(Z) -> GL_k(Z/n)) = {M in GL_k(Z/n) : det M = +-1 mod n} = det^{-1}({+-1}),

of index `phi(n)/2`. `diag(2,1)` modulo 5 has determinant `2`, so it is not in the image and has no integral
unimodular lift at all. The image **is** the whole group exactly when `phi(n) <= 2`, i.e. `n` in `{1,2,3,4,6}` --
which is why the error is invisible on the small moduli and must not be generalised from them.

The distinction the error collapsed is **matrix-group surjectivity against vector-orbit transitivity**. A proper
image can still act transitively on vectors. Measured by direct enumeration of the image and its orbits (a probe
over all `k x k` matrices over `Z/n`, not a port API -- the port does not expose these orbits, see below):

| `k` | `n` | `|im|` | `|GL_k(Z/n)|` | index | orbits on `(Z/n)^k` |
| --- | --- | --- | --- | --- | --- |
| 1 | 5 | 2 | 4 | 2 | 3: `{0}`, `{+-1}`, `{+-2}` |
| 2 | 5 | 240 | 480 | 2 | 2: `{0}` and all 24 nonzero |
| 2 | 7 | 672 | 2016 | 3 | 2: `{0}` and all 48 nonzero |
| 2 | 6 | 288 | 288 | 1 | 4: sizes 1, 3, 8, 24 |
| 2 | 2 | 6 | 6 | 1 | 2: `{0}` and the 3 nonzero |

So the rank-one `+-` verdict does not transfer to rank two, but the reason is the **orbit count on the image**,
not surjectivity; and "proper at rank one only" was wrong as stated, since the image is proper at rank two too. The
valid part of the previous revision survives unchanged: the explicit witnesses (the `[[A,0],[B,D]]` blocks with
`D = [[2,1],[5,3]]` and friends, `B` absorbing `s - r D`), and every specimen's verdict. Convention note: that
`D` is the **column**-convention block (`D (1,0)^T = (2,5)^T = (2,0)^T`); the port's row convention writes the
same transport as `(1,0) D^T = (2,5)`, i.e. `D^T = [[2,5],[1,3]]`. The image is closed under transpose, so
membership is the same statement either way, but the arithmetic must not be mixed between them.

## What replaced it: the maintained group, orbits, stabilizers and the word section

`EichlerRecursion.radical_congruence_image(lattice, modulus)` returns a `RadicalCongruenceImage` whose `group` is
**Sage's own** `MatrixGroup` over `Zmod(modulus)`, generated by the reductions of integral generator lifts
(`identity_matrix` for the elementary matrices, `diagonal_matrix` for the sign), with those lifts retained.

Every question the object answers is answered by maintained machinery:

- `order` is `MatrixGroup.order()` (GAP), **not** an order formula re-derived here;
- `general_linear_order` is `GL(k, Zmod(n)).order()`, and `is_proper`/`index` are its comparison with `order`;
- `contains` is `matrix in group`;
- the theorem is then checked, not assumed: every generator lift has determinant `+-1`, so the image lies inside
  `det^{-1}({+-1})`, and its order equals that preimage's order computed from `GL` and `euler_phi`.

There is no modular matrix arithmetic, no group closure, no element enumeration and **no order bound** in the port:
an earlier draft had all of those plus a 4096 cutoff, and that draft is deleted, not retained.

The transporter with an integral lift is **supplied**, and an earlier revision of this note was wrong to call it a
missing owner capability: the calls behind that claim were ill-typed. GAP's documented chain works once the points
live in the ring of the matrices:

    ring = libgap.ZmodnZ(modulus);  one = libgap.One(ring)
    point = libgap([libgap(entry % modulus) * one for entry in row])     # not an integer list
    orbit = libgap.Orbit(group.gap(), point, libgap.OnRight)
    action = libgap.ActionHomomorphism(group.gap(), orbit, libgap.OnRight)
    permutation = libgap.RepresentativeAction(Image(action), i, j, OnPoints)
    element = libgap.PreImagesRepresentative(action, permutation)
    word = libgap.PreImagesRepresentative(EpimorphismFromFreeGroup(group), element)

**Sentinel contract.** `Position` answers GAP's `fail` for an absent entry, not `false`: libgap returns a
`GapElement_Boolean` whose string is `'fail'`. An earlier revision tested `str(position) == "false"`, which is never
true, so the missing-target case fell through to `RepresentativeAction` with a `fail` argument, and *that* `fail`
was read as "no carrier". The two facts are now separated -- an exhaustive orbit nonmembership returns `None`, while
a `RepresentativeAction` failure after both positions are present raises, because the image acts transitively on its
own orbit and such a failure is an undecided execution, not a decision. The regression is direct and non-vacuous:
rank one, modulus 5, `1 -> 2`, with the GAP sentinel itself asserted alongside it.

`RadicalCongruenceImage.transporter` composes the integral lifts along that word -- the lift-word obligation, which
is the port's own data -- and verifies unimodularity and the transport before returning; the reversed letter order
is a different matrix and is rejected by that verification rather than returned. `orbit_of`, `stabilizer_order` and `stabilizer_generators`
use GAP's `Orbit` and `Stabilizer` with the same typing; the last lifts GAP's stabilizer generators by their words
and the test checks that those lifts generate a group of exactly `stabilizer_order` elements (1, 2 and 10 for the
#41 specimens). The full trace, the three failing calls and why each failed
are in `.tmp/handoff-owner-congruence-transporter.md`, which is now a resolved record and not a request.

## Where the boundary actually is

The first of #41's three open items is discharged, now on the correct statement:

- **the image of `GL(R)` in `Aut(R/xR)`**: it is `det^{-1}({+-1})`, proper whenever `phi(x) > 2`. At `R = Z` it is
  `{+-1}`, so `s = +- r (mod x)` is the whole test and a dropped sign is a false negative -- the sign cases are
  pinned separately. At `R = Z^2` it is the index-two subgroup of `GL_2(Z/x)`, whose action on `(Z/5)^2` happens to
  have the same two orbits as the whole group; that is computed by `orbits()`, not inferred. The retained public
  route gets every specimen right, and the witnesses show the integral lift.

Still open under #41, and not discharged by the above:

- the general statement for an arbitrary `R`, not `Z^k`: the criterion is the split-radical one and the tests are on
  `Z` and `Z^2`, not on a ring with torsion or a non-free radical;
- lazy/infinite orbit sets: `c = 0` (the condition is exactly `D r = s`), and marked vectors whose quotient image
  has unbounded content, where a finite orbit list is a false claim;
- downstream **orbit-set** consumers (the congruence-pair consumer is now supplied and tested; the orbit-set
  consumers are not).

Pointwise stabilizers are now cross-checked against the image: for `v = (x, r)` the stabilizer maps **onto**
`{A x = x} x {D : r D = r (mod c)}` with kernel `{D : r D = r, D = 1 (mod c)}`. At radical rank one that kernel is
trivial, so the stabilizer's order equals the image's count (`(5,1)` is rigid, order 1; `(5,0)` has order 2). At
radical rank two it is not: `D = [[1,5],[0,1]]` fixes `r` modulo 5 and is unimodular, so the stabilizer is infinite
while its image is one of ten pairs, and the port reports `+Infinity` for the generated group. The finite count is
an image, never an order.
